# 私人秘书系统规格

这份规格是工作区和服务的唯一行为边界。它描述一个用户、一台服务器和一份 Markdown 笔记的轻量系统，不把用户绑定到某个模型或 QQ 框架。

## 1. 产品原则

- 极简、低摩擦，用完即可离开。
- Markdown 是正文唯一真源；SQLite 只保存必要的运行状态，不保存日记、文章、模板或知识库全文。
- 习惯只判断约定行为是否发生；任务判断明确成果是否达标。两者不能互相冒充。
- 不要求每日评分、断签惩罚、长篇汇报或无限追问。秘书像秘书一样给出必要的下一步，少问问题。
- Agent 只负责理解、提案和短文案；Core 决定读写、执行、调度、投递和权限。

## 2. 目录与职责

```text
MOC.md                    主页、热力图和入口
01. Daily/                日、周、月、季、年计划与日记
02. Decisions/            问题研究和决策记录
03. Manual/               可复用技能、步骤和检查清单
Someday.md                暂时不承诺的想法和可能性
Template/                 周期和日记模板
Attachment/               所有图片和文件附件
.agent/                   秘书配置、提示词、契约和运行状态
.dev/secretary-service/   与笔记数据分离的服务工程
```

`Someday.md` 是一个开放的停放区：记录值得保留、但当前不承诺时间或结果的想法。它不是总体目标、任务或习惯，不触发提醒、不计入完成率，也没有分类或固定格式；想记什么就直接写什么。以后想做时，再自行把其中一项转入 Daily、Decisions 或 Manual，也可以一直保留或删除。

## 3. 日历与层级

- 使用自然年、自然季度、自然月；季度为 1—3、4—6、7—9、10—12 月。
- 周目录使用 ISO 周号；跨年周在两个自然年各保留一份对应片段，日记始终归入当天自然年和自然月。
- 年 → 季 → 月 → 周 → 日逐层引用。父级只提供当前层需要的重点和边界，子级不复制父文正文。
- 已存在的历史笔记原样保留，不批量迁移、不重写、不套新模板。

```text
01. Daily/YYYY年/
  年度计划.md
  第1季度/季度计划.md
    01月/月度计划.md
      YYYY-Www/周记.md
        YYYY-MM-DD.md
```

统一日历服务负责创建缺失的父级和日记，并保留用户已有正文。Web、QQ、Obsidian 入口不能各自复刻日期规则。

## 4. 模板边界

日记只保留可直接填写的标题和复选框：习惯、任务、善意与美好、禅、改进、随笔。禅用于记录念头、动机、情绪和“我在期望什么”，不是评分表或心理问卷。

周记负责把本周接回月目标，观察连续性并决定下一轮怎么调整；不复制“本周日记”或逐日流水账。月、季、年笔记负责本级选择、取舍和下一层安排，不做无用途的重复汇总。模板内不写需要每次删除的说明文字、机器字段或维护步骤。

## 5. 习惯、任务与安排

- **习惯**：最低标准是行为发生。数量和质量可选，未提供数量不能被猜成失败。
- **任务**：必须有可检查的交付条件；开始、部分完成和达标分别记录。
- **安排**：时间窗口、提醒上限和静默时段由 Core 确定，模型不能直接改系统时钟。
- **事实**：用户消息、日记复选框或经过验证的工具证据形成事实；沉默不等于没做。

长期定义、当前安排、每日事实和更正写入 `.agent/state/` 中的 JSON 文件。SQLite 只保存幂等、恢复、短期消息、事件和投递记录，并按保留期清理。

## 6. 运行链路

```text
Web / QQ
   ↓
Core（唯一业务写入者、权限和调度控制者）
   ├─ Markdown / Attachment
   ├─ .agent/state/ 长期事实
   ├─ SQLite 短期运行状态
   ├─ Git 备份
   └─ AstrBot（受限理解与文案） → NapCat（QQ 登录与 OneBot v11）
```

AstrBot 不挂载笔记、SQLite、Git、密钥或宿主路径，不能使用 Shell、任意 HTTP 转发或直接发送 QQ。NapCat 只持有 QQ 登录会话。生产 Core 只在配置了 AstrBot bridge 后启用该通道，否则安全降级。

## 7. Agent 与工具

AstrBot 只加载本项目插件，工具白名单固定为 `get_context`、`secretary`、`workspace`、`submit_proposal`。

- `get_context`：读取本回合所需的短上下文。
- `secretary`：查询和提交习惯、任务、安排、状态及恢复操作。
- `workspace`：在 Core 授权的 Markdown、模板和 Attachment 范围内读写。
- `submit_proposal`：把业务变更交回 Core 校验；没有 Core 回执不能声称成功。

普通文件工具拒绝 `.agent/`、`.git/`、`.obsidian/` 内部文件、路径穿越、符号链接越界和任意外部目录。模型上下文按最小必要原则提供；日记中的禅、改进、随笔等叙述只有用户明确授权分析时才读取。

## 8. 语言与交互

秘书使用简短、尊重、具体的中文，遵循非暴力沟通和卡耐基式的友善原则。先回答当前问题，再给一个必要的下一步；不把用户变成被审问对象。提醒只说明一件主要动作，支持“做了”“跳过”“晚些时候”等自然反馈。静默、预算和用户暂停优先于模型的催促。

## 9. Web

Web 是响应式单用户编辑器和状态入口。它读取和保存服务器工作副本，支持 Markdown 编辑、日历层级、搜索、附件、事项、助理消息和运行状态。正文保存使用版本校验和幂等键；并发冲突返回 409，保留用户草稿和服务器版本。浏览器草稿放 IndexedDB，不在 SQLite 建正文副本。

## 10. SQLite 与恢复

SQLite 只覆盖 schema 元数据、文档索引、入站去重、事件和出站投递等最小表。启用 WAL、单 Core 写锁、迁移、租约、幂等键和重启恢复。发送未知时不盲目重发；失败重试受窗口和预算限制。损坏数据库隔离保存并暂停旧主动投递，安全的纯 Markdown 保存仍可继续。定期清理短期消息正文和回执，不能删除长期事实。

## 11. QQ 与主动提醒

生产通道固定为 NapCat → AstrBot 插件 → Core。只接受绑定的机器人账号和唯一使用者私聊；陌生人、群消息、其他机器人和伪造来源拒绝。Core 以固定 tick 检查已批准的时间窗口，遵守静默时段、每日总量、单事项上限和最小间隔。Web 与 QQ 使用同一业务状态，不各自维护任务。

## 12. Git 与数据边界

服务器工作副本是运行源；Git 只作为用户指定私有数据仓库的自动备份。备份允许 Markdown、Attachment、长期 `.agent/state/` 和必要上下文；数据库、密钥、日志、`.dev/`、Obsidian workspace 和浏览器草稿永不进入备份。远端冲突停止推送，保留双方，不强推、不自动覆盖。

## 13. 安全与部署

服务代码与笔记数据分离。Core 只获得笔记根目录；生产容器使用非 root 用户、只读镜像、最小网络和内部 bridge token。公开 Web 必须使用 HTTPS、单用户安全会话、同源写入校验和速率限制。真实凭据只放部署目录的独立 secret 文件，绝不写入笔记、源码、日志、模板或示例。

## 14. 变更与验收

先用隔离库、模拟模型和模拟 QQ 开发，再做真实接入。真实模型、QQ、域名和 Git 备份未实测时必须明确标记为未验证。关键验收包括：习惯和任务不混淆、跨年日历、日记并发、权限边界、重复输入、未知投递、重启恢复、SQLite 清理、NapCat 主动发送、Web 与 QQ 共享状态、私有 Git 失败降级和整机恢复。

验收记录见服务工程的 `docs/ACCEPTANCE.md`；部署维护见 `docs/OPERATIONS.md`。模板仓库不得包含私人日记、历史审计输出、二维码、运行 bundle、服务器地址、账号、密钥或临时联调脚本。
