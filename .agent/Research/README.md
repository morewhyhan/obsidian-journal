# 私人 AI 助理

**把一次交代，接成后面有人跟进的事情。**

本文介绍产品要交付的体验。工程设计以 [ARCHITECTURE v2.2](ARCHITECTURE.md) 为准；下列体验不代表该版已全部实现。当前实现、历史测试和未完成部分集中在 [DDD](DDD.md#13-验证方法与已知边界)。

在QQ里说清要做什么，助理保存任务和安排、按约定提示、记录反馈，并在计划被打乱后继续处理。正文留在自己的Markdown笔记里。你处理完当前事情就能离开，下次回来接着说。

这对三种情境尤其有用：事情交代过却容易散掉；计划经常被临时变化打断；为了管理自己，反而要花很多时间填表和重新解释。

## 你交代以后，会留下什么

| 你的话 | 系统实际保存/处理 | 带来的用处 |
| --- | --- | --- |
| “明天十点写报告，十一点结束，六点截止，验收是第一节写完并检查。” | 成果、验收、执行窗口、硬截止和对应日记条目 | 后续能判断何时开始、做什么、怎样算完成 |
| “这几件先讨论，暂时别办。” | 待决定方案；接受后再落实 | 可以把想法谈清楚，不把讨论误变成承诺 |
| “报告还需要半小时。” | 实际进展与相关安排的影响 | 检查后续依赖和固定事项，能调的调，需要取舍的给建议 |
| “先用现有案例，素材来源等我定，下周再问。” | 当前共识、未决问题、下一步和检查点 | 下次不用从头讲，清理短期聊天或重启后仍能接续 |
| “今天只读了一句，没读到十句。” | 按已约定最低行为记录 | 一句是最低标准时，就记为发生；可选目标不会变成压力 |
| “今天别催这份报告，任务保留。” | 相应联系暂停，承诺仍在 | 可以安静做事，后续仍找得到这件事 |

## 一段使用过程

> 你：先讨论明天的词汇、语法和报告，不要执行。
>
> 助理：结合已有记录整理待定内容，缺少关键条件时补问。
>
> 你：差不多了，整体说一下。
>
> 助理：复述当前版本，指出确实需要取舍的地方。
>
> 你：就这样做，语法的截止改成下午六点。

助理按接受后的版本一起落实，保存实际结果并更新日记。到约定条件时给出下一步提示；你说“开始了”“还差一些”“资料没到”，后续处理会根据事实变化。台词只是示意，实际语言由模型生成。

## 日常怎么用

先告诉助理真实可用时间，例如工作日上午十点到十二点。任务说明想交付什么，习惯说明最低行为。提醒时间、规划时刻和联系频率可以调整；番茄钟、小时回顾按需开启。

默认晚间准备第二天：索引必要的年、季、月、周重点，按模板补缺失笔记，再把确定的安排落实到日。上层为空就保持空白；新建议仍等你接受。已有正文和私人随笔保留。

## 现在能信到什么程度

任务/习惯分开记录、多项决定、模板联动、延误处理、规则记忆和跨会话接续已有历史程序与实际模型证据。证据只适用于当时版本和测试范围，不等于 ARCHITECTURE v2.2 验收通过。该版列明的责任步骤、受限后台委托、准备与联系解耦、费用预留及恢复等要求，仍须逐项实施核验。

仍有边界：自然语言可能误解；外部条件没有数据来源时需要你核对；QQ连接受登录状态影响；任意脚本和未支持自动化不能仅靠一句话获得能力。长期能否减少负担、帮助行为稳定发生，需要真人使用验证。

系统不会把沉默当没做、把计时结束当完成、把渠道接受当你已读。无法同时满足截止与固定安排时，它需要你作必要取舍。
